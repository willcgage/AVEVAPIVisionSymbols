# Third-party components

## Nothing third-party is deployed

The installed library — everything under
`Scripts\app\editor\symbols\ext` — contains no third-party code. It is PVX
source only, plus the SVG icons, all written for this project. No framework, no
charting library, no polyfill, no web font, no CDN reference.

That is enforced, not merely intended: the build validator rejects a symbol that
references anything outside the library, and `docs/DEPLOYMENT.md` documents three
commands that let you confirm it against a package you have been handed rather
than taking this file's word for it.

PI Vision supplies AngularJS 1.x and its own dependencies to the page. PVX uses
the AngularJS that PI Vision has already loaded; it neither bundles nor upgrades
it. A PI Vision licence does not grant rights to the third-party libraries PI
Vision itself ships — notably Kendo UI — and nothing here uses them.

## Development-only dependencies

These exist to build, preview and test the library. None reaches a PI Vision
server.

### AngularJS 1.8.3 — `dev/vendor/angular.min.js`

| | |
|---|---|
| Licence | MIT |
| Copyright | 2010–2020 Google LLC |
| Home | https://angularjs.org |
| Used by | `dev/harness.html`, the offline preview harness |
| Deployed? | **No** — `dev/` is excluded from `dist/` and from the installer |

The preview harness mimics PI Vision's own host environment so symbols can be
developed without a server. PI Vision is an AngularJS 1.x application, so the
harness needs the same framework to be a faithful stand-in.

It is vendored rather than fetched so the harness works on an air-gapped build
machine.

**AngularJS reached end of life in December 2021 and receives no security
updates.** That is accepted deliberately: it runs only on a developer's own
machine, against synthetic data, from a local file. It is not a dependency of
anything that ships. If a scanner flags it, this paragraph is the answer — and
the version here is pinned to match what PI Vision itself hosts, so replacing it
with a maintained framework would make the harness *less* faithful, not safer.

### Playwright — `package.json` devDependency

| | |
|---|---|
| Licence | Apache-2.0 |
| Copyright | Microsoft Corporation |
| Home | https://playwright.dev |
| Used by | `tools/verify.js`, `tools/probe.js`, `tools/test-api.js` |
| Deployed? | **No** |

Drives headless Chromium for the 558-check render gate, the single-symbol probe,
and the PI Web API test suite. The only entry in `package-lock.json` apart from
its own transitive `playwright-core` and the optional `fsevents`.

Not required to build. `node tools/build.js`, `tools/wix.js` and
`tools/docgen.js` run on a bare Node installation with no packages installed —
see the air-gapped section of `docs/DEPLOYMENT.md`.

### WiX Toolset v3 — release pipeline only

| | |
|---|---|
| Licence | Microsoft Reciprocal Licence (MS-RL) |
| Home | https://wixtoolset.org |
| Used by | `.github/workflows/release.yml`, to compile the MSI |
| Deployed? | **No** — it is a build tool; its output is the MSI |

Installed on the GitHub Actions Windows runner at release time. The `.wxs` source
it compiles is generated by `tools/wix.js` from the build output.

`wixl` (from GNU msitools, LGPL-2.1+) is used in CI on Linux to compile the same
source for structural validation on every pull request. It is a build tool as
well, and ships nothing.
