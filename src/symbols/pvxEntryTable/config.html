Rows
Set this and every row below can be a bare attribute name. That is the difference between a readable twenty-row sheet and twenty lines of near-identical eighty-character paths. A row that starts with \\ is treated as a full path and ignores this.
Grammar
path | label | units | min:max
Only the path is required; drop any field from the right. To skip a field but keep a later one, leave it empty: Bed Temp | | degC.
A worked example. With the element path set to \\AFSERVER01\Production\Reactor1, this sheet:
# 06:00 rounds
Catalyst Charge | Charge | kg | 0:500
Bed Temp | Bed temperature | degC | 0:900
Tank Level
\\AFSERVER01\Production\Cooling|Basin Temp | Basin temp | degC
gives four rows. The third takes its label from the attribute name and has no range. The fourth points at a different element entirely, so it is written out in full. Lines starting with # are notes and are skipped.
Why the spaces around the | matter. An AF path already contains a pipe, between the element and the attribute. So the rule is: a pipe with a space beside it separates fields, and a pipe with no space belongs to the path. That is why the fourth row above resolves to Cooling|Basin Temp and not to an element called Cooling with a label of Basin Temp. Write full paths without spaces around their pipe, and put spaces around the separators, and the two never collide.
A row that does not resolve is marked no path and disabled. The other rows carry on working — one mistyped line in a rounds sheet must not take the sheet down with it.
This symbol writes through PI Web API, not PI Vision's data pipeline. PI Web API on this PI Vision server needs no setup. If the symbol says it cannot reach PI Web API, open ext/piwebapi-check.html, which says what to change. Who may write is decided by PI and AF security, not by this symbol.
Submitting
Leave this on. There is no undo on a PI write. The confirmation lists every value with the row it is going to, by name — a summary that only said "write 4 values?" would be a button people learn to click without reading.
On (the default): only the rows that were filled in are sent, and the blanks are simply not written. Off: every row must have a value before the button enables — for a regulatory rounds sheet where a missing reading is itself the problem. Either way, a row with an invalid value stops the whole submit: which of the operator's readings to keep is not the symbol's decision to make.
Only the rows that actually saved are cleared. Clearing a row that failed would throw away a reading the operator still has to send, and by then they may not remember it.
Timestamp
"When they are written" sends * and lets PI stamp them — the historian's clock is the authority and a browser's is routinely minutes out.
"One time for the whole sheet" is the normal choice for rounds: the readings were taken at 06:00 and typed in at 07:15, and they belong at 06:00.
"A time per row" is for a walk that takes an hour, where each reading has its own moment. It costs a second field on every row, so use it only when that is true.
Both accept 2026-08-08 06:00 or * with an offset such as *-2h. Future timestamps are rejected: they are nearly always a typed year or a mixed-up day, and they sit in the archive ahead of every real value until they arrive.
What the sheet shows
Fetched for the whole sheet in one request. Seeing the last value beside the box is the cheapest guard against a transposed digit there is. The column drops itself automatically when the symbol is too narrow to hold it.
This symbol has no PI Vision data pipeline, so nothing else will refresh it. The refresh pauses while a confirmation is open or a submit is in flight, and it never touches a value the operator has already typed.
PI has no transaction: ten writes are ten independent facts and the ninth can fail while the rest succeed. This column is where that gets said honestly, row by row, instead of collapsing a partial success into "failed" and sending the operator back to re-type nine readings that are already in the historian.
Tighter rows for a long sheet in a short symbol.
Chrome
Below roughly 200 × 140 pixels the sheet is not usable and the symbol says so by name instead of drawing a squeezed version of itself. A cramped entry field is a mis-typed write waiting to happen.
Advanced
Renders the whole sheet and refuses to write. This is for building and reviewing a display before the AF write permissions exist, so the layout can be agreed without anyone putting test numbers into the historian. Clear it when you go live.
