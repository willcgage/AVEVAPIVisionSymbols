Where the tree starts
This symbol reads the AF hierarchy from PI Web API, not from PI Vision's own data pipeline. Leave the database blank to use the database of the attribute dropped on it, or of the display's asset. PI Web API on this PI Vision server needs no setup. If the symbol says it cannot reach PI Web API, open ext/piwebapi-check.html, which says what to change.
Start below one element instead of at the database root — one navigator per area, without making the operator walk down through everything else first. When this is set the database path is not used.
1 means the root is open and its children are listed. Every extra level is one request per branch at the level above it, so raising this on a wide hierarchy is the one setting here that can make the display slow to open. Deeper levels load when they are opened.
What the tree shows
The list and the drop-down fetch every element under the root in one request, up to the most per level below, and say so when there are more. The drop-down fits a display header: it shows the display's current asset, and choosing another switches to it.
Applied by PI Web API at every level as it loads, so an intermediate element that does not use the template hides its whole subtree. Use it where the elements you want share a level (all the Units under an Area), not to pick one type out of a mixed hierarchy.
* and ? wildcards, as in PI Web API. Same caveat as the template filter: it hides non-matching branches along with everything beneath them.
If a level holds more, the footer says which one was cut and how many are shown. It never silently truncates.
A value on each row
The name of an attribute on each element, such as Status or Discharge Pressure. Its current value is shown at the end of every row on screen with a coloured dot, read through PI Web API and refreshed on the interval below. A row whose element has no such attribute shows a dash.

Colours for digital states

Search
Characters. Search runs on the AF server across the whole hierarchy below the root — it does not walk the tree in the browser, so it finds elements in branches that have never been opened. Down and Enter move from the box straight into the results.
Selecting an asset
Sets this display's asset rewrites the ?asset= parameter, which is the PI Vision contract every other symbol on the display already follows — one click here re-points the whole display. Both navigates when a target display is set and falls back to setting the asset when one is not, so a half-configured symbol still does something rather than nothing.
The selected element's AF path is passed along as the target display's asset.
Following the display
Marks the row matching the display's ?asset=, however it was set — by this symbol, by another symbol, or by the link the operator arrived on.
Without this, reopening a display shows a collapsed tree with the current selection invisible somewhere inside it. If the asset is not under this root the footer says so and nothing is expanded.
