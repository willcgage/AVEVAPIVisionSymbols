How this works
This symbol folds the display's own time range; it cannot fetch other ranges. A PI Vision custom symbol only ever receives the window the display is set to, so it cannot ask for "the same shift last week" — that needs the PI Web API. Instead it cuts the one window it is given into equal periods and lays them on a shared relative-time axis. The one exception is Runs from event frames below, which reads the event frames through PI Web API.
So: to compare seven days, set the display time range to 7 days and choose a 1 day period. To compare three shifts, set the range to 24 hours and choose the shift period. If the display range is shorter than one period there is nothing to compare, and the footer says so instead of drawing something misleading.
The first data source is folded in full. Each further one draws its current period on the same axis in its own colour; for tags in different units, show % change below, where each is measured from its own baseline.
Period
Chosen from the length of the display range so the symbol is useful before it is configured: under 48 hours folds by the hour, under 14 days by the day, otherwise by the week.
Shifts are counted from that hour on each day, in the browser's local time — the same clock the control room reads.
Each period starts on the 1st and the axis is the day of the month; shorter months end early. Months always follow the calendar, whatever the alignment below.
Each event frame in the display's time range is one run: a batch, a campaign, a start-up. The event frames are read from PI Web API; the values are still the ones PI Vision sends, cut at each run's start and end, so a run that began before the time range is drawn from where the range starts, and the footer counts it.
At the start, the axis is the time since each run began; at the end, the time before it ended. 0 to 100% stretches each run to the same width, so a short batch and a long one line up step by step.
Event names, comma separated, * and ? allowed. The golden runs are always shown, however old, and their average with a band either side replaces the envelope: 5% of the average, 2 in the tag's units, or 2s for two standard deviations of the golden runs (which needs two of them). The current run is measured against it. Leave blank to compare with the older runs.
Periods start on real boundaries — midnight, the shift start, Monday. 08:00 on one trace is 08:00 on every other, and the axis is labelled in clock time. This is the right answer for "Tuesday against Wednesday". The newest period is still in progress, so its trace stops part way across.
Periods count back from the end of the window, so the newest trace always ends at "now" and the axis is labelled in elapsed time. This is the right answer for "the last 8 hours against the 8 before that". These two settings answer different questions — pick the one that matches yours.
Every period is drawn as its difference from the baseline at the same point in the period, around a zero line; the envelope is then the older periods' spread around it.
The most recent N are kept. Anything older is dropped and counted in the footer, so the chart never quietly shows less history than the range contains.
One query covers every period at once, so this budget is shared between them. Eight periods at 800 points is 100 samples each.
Envelope
Computed for each point on the relative axis, not as one band across the whole chart: what matters is the range the process occupied at this point in the period. Percentiles and standard deviation need at least two older periods to mean anything; with only one the symbol falls back to min/max and says so.
Leave unset to use the accent colour.
Traces
The history recedes into the background and only the current period keeps its colour — the fastest way to answer "which line is today". The legend collapses to current / older / envelope, because faded traces cannot honestly be listed one by one.
Every period gets its own hue and its own legend entry. Worth it when you need to name a specific past period rather than read the envelope.
Periods are resampled onto a shared relative-time grid before they are overlaid — without that, traces with different sample counts would not line up. The grid keeps each slot's minimum and maximum, so excursion spikes survive.
Axes and chrome
Leave either box blank to keep that end automatic.
Auto uses dates when the period is a named stretch of the calendar and offsets otherwise — on a four-hour fold "-8 h" says more than a timestamp.
How much of the current period sits inside the envelope, and the largest departure from it. The share is measured from each slot's average so one stray sample cannot condemn a slot; the departure is measured from the extremes, because a two-minute spike out of the envelope is exactly the event worth reporting.
Below roughly 200 × 140 px the panel, the legend and the axis titles are dropped; below 140 × 100 px the tick labels go too.
