Latching
Each tile latches. A point that goes out of limits stays lit until someone acknowledges it — including a point that goes out and comes back between two refreshes, which a live status tile can never show you. An unacknowledged alarm that has already returned to normal flashes slowly (the ISA‑18.2 ringback state) and does not clear itself.
Scope: by default the latch and every acknowledgement live in this browser tab only. They reset when the display is reopened or refreshed, and they are not shared between operators — two people on the same display acknowledge independently. Turn on Shared acknowledgement below to store acknowledgements in an AF attribute instead, so every screen sees them and they survive a reload.
In threshold mode a bad-quality reading freezes a tile instead of moving it: a value you cannot trust is not evidence of an alarm or of a return. Frozen tiles are drawn with diagonal stripes.

Acknowledgement
Tiles are keyboard reachable and acknowledge with Enter or Space. Choose “Neither” for a wallboard nobody stands at — tiles then latch and never clear.
Shared acknowledgement
Off by default, because it cannot be otherwise: it needs a PI Web API this display can reach and a String attribute provisioned in AF to hold the record. With it on, an acknowledgement made at one screen appears on every other screen pointed at the same attribute, and survives reopening the display.
A String attribute, which this symbol keeps a small JSON map in — one attribute for the whole panel, not one per alarm. Everyone who acknowledges needs write access to it; PI and AF security are the access control, and a refusal appears on the panel as a banner rather than being swallowed.
How long another operator’s acknowledgement can take to appear here. Your own is immediate. Shorter costs a PI Web API read per display per interval, so leave it at 15s unless a control room needs faster.
Recorded against every acknowledgement made here. Leave it blank and “unknown” is recorded and displayed — the browser cannot reliably know which PI Vision user is at the screen, and a wrong name on an acknowledgement is worse than no name. Where it matters, set it per control-room display to the panel or position it lives on (“Panel 1”, “Board Operator”), which is a fact about the screen and therefore actually true.
Adds the acknowledging name and how long ago to acknowledged tiles, where the tile is big enough. The full version is always in the tile’s tooltip.
What this does not give you: PI Web API has no compare-and-swap, so two operators writing in the same instant is handled by re-reading, merging and verifying — not by a transaction. When a write cannot be made to stick the panel says so and tells you to acknowledge again; while the store is unreachable, tiles fall back to acknowledging in this browser only and the panel says that. If acknowledgement must be guaranteed, this is not the mechanism — an AF analysis or PI Notifications is.
First out
The first tile to alarm inside the window gets a corner wedge and a 1ST legend; everything that follows within the window is treated as a consequence. In a trip cascade this is the tile that says what actually happened. Points already out of limits when the display opens are never marked — they all arrived at once, so none of them was first.
Flash
One full cycle, in milliseconds. Viewers who have asked their operating system to reduce motion get a static outline instead of a flash, whatever this is set to.

Colour
An alarmed tile takes the colour of the threshold band it landed in, so a Critical tile and a High tile are visibly different problems. Acknowledgement keeps that colour — it removes the flash and adds a tick, it does not repaint the severity away.

Advanced
Only used when shared acknowledgement is on, and only a testing escape hatch — leave it blank in production. The base URL belongs in ext/libraries/pvx/pvx-config.js, where one site setting serves every symbol and survives an upgrade. Use this to point at a second PI Web API: a test instance, or another plant's server. It moves the base URL for every PVX symbol on the page, because PVX.api is deliberately one shared client so that authentication is configured once per site. Two symbols with two different overrides on one display will fight.
