Profile
A fingerprint answers "does this asset still look like it used to". It is built for recognising a changed outline, and it is a poor instrument for comparing magnitudes — the axes carry different units and each is normalised separately, so a longer spoke does not mean a bigger number. Use a ranked bar chart when the question is "which is largest".
Everything except Current value is calculated by PI Vision over the display's time range.
Beyond about a dozen spokes the labels collide and the outline stops being memorable. Extra sources are dropped from the end and counted in the footer. Three axes is the minimum — fewer is a line, not a shape.
With rows from an AF search naming three or more attributes, the attributes are the axes and every asset found is one outline over the others, in its own colour: a fleet's fingerprints on one web. With one or two attributes the assets are the axes and each attribute is an outline. Assets are paired by path, so an asset missing an attribute shows a dent at the centre and is counted in the footer. Series below does not apply.
Axis scaling
Per axis, fixed limits is the only mode where the shape means the same thing tomorrow as it does today, because the limits do not move when the data does. Use it for any display you intend to save.
Per axis, from the data runs each axis from zero to its own largest value on screen, so the same outline can describe different readings on different days — and the larger of the two profiles always touches the same radius, which means you are reading the gap between them, not the outline. It also needs two values on an axis to have an extent at all, so with Current only selected there is nothing to measure and every axis falls back to the shared scale (the footer says so).
One shared scale puts every axis on the same numbers. Honest only when the units genuinely match — otherwise the °F axis buries the mils axis at the centre.
One min:max entry per axis, comma separated, in the same order as the data sources. Leave an entry blank (or between two commas) to let that axis use the data extent. Malformed entries do the same and are reported in the footer, so a typo in one axis never blanks the others.
Profiles
Current over a reference and Compare two halves both split your data sources down the middle: the last half becomes the second profile and is paired positionally with the first half, so source 1 shares an axis with source (N/2)+1. Add the "known good" attributes in the same order as the live ones. An odd source count leaves one unpaired; it is dropped and named in the footer. The reference is drawn behind and dashed; in compare mode both are filled equally.
Shape
0 leaves the outline only, which is easier to read when two profiles overlap heavily.
0° puts the first axis at 12 o'clock; positive turns clockwise.
Web
Below roughly 220×180 px the web and the labels are dropped automatically and only the outline is drawn; below 140×100 px the legend goes too. A small tile still has to show a shape.
Labels
Labels sit outside the outer ring and are truncated to the real space left at their side of the frame. The full name is always in the tooltip.
Current profile only. Numbers on a radar collide easily; the tooltip on each point is usually the better place to read one.
Drawn along the first axis. With a per-axis scale they describe that axis only — they are meaningful for every axis just in One shared scale.
Colour
Turns "the shape changed" into "this axis is abnormal" — each point takes the colour of the band its raw value falls in, while the outline keeps the profile colour. Needs Enable thresholds below; the bands are compared against the raw value, not the normalised radius.
