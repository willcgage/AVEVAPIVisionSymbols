Menu entries
A string attribute whose value is the menu, written as below, so one menu kept in AF serves every display that shows it. Start the path with |, such as |Display Menu, for an attribute of the display's asset (else of this symbol's data source element): each asset can then carry a menu of its own. Read through PI Web API once a minute; until it answers, and if it cannot, the list below is shown and the bar says why.
One entry per line, Label | target | options. Indent a line under another to put it in that entry's menu, as deep as you like (or start it with one > per level). --- draws a separator.
Target — a display id such as 101, a display address, or a web page starting https://. An entry with entries under it needs none.
Options — separated by ;: asset= an AF path, start= and end= PI times, tab=new, keeptime=no, keepasset=no.
Icon and tooltip — [home] Overview -- Plant overview | 101. A label of only an icon makes an icon entry. Icons: home, back, forward, up, down, trend, alarm, table, gauge, clock, map, list, settings, info, report, power, star, menu, external, kiosk, toolbar, timebar, sidebar, plant, search.
A line with no target and nothing under it goes nowhere, so it is left out and the bar says so.
Layout
Behaviour
A web page opens in a new tab unless its entry says tab=same. An entry's own options win over these.
Nothing navigates while the display is being edited; the menus still open, to check them.
Buttons on the bar
Each switch adds or removes a part of the display's address (mode=kiosk, hidetoolbar, hidetimebar, hidesidebar) and loads the display again. They stay set as the menu, and any PVX navigation, moves between displays. Keep a way back: in kiosk mode this menu may be the only one left on the screen.
Logo
0 fits the bar.
An image on PI Vision's own server loads anywhere the display does. The bar says so if it does not load.
