Event source
This symbol reads Event Frames from PI Web API, not from PI Vision's own data pipeline. Leave the database blank to use the database of the attribute dropped on it, or of the display's asset. PI Web API on this PI Vision server needs no setup. If the symbol says it cannot reach PI Web API, open ext/piwebapi-check.html, which says what to change.
* and ? wildcards, as in PI Web API.
Overlapped is the only mode that is arithmetically right for downtime accounting, and it is the default for that reason: an event that started before the window and is still running consumed time inside the window, and every stricter mode drops it. Inclusive returns only events that both started and ended inside the window, which quietly under-reports the outage that is happening right now.
If more match, the footer says so — and says that the ranking may be wrong, not merely that some events are missing. PI Web API returns the first N by start time, not the N that matter, so a truncated result can put the wrong reason code at the top.
This symbol has no PI Vision data pipeline, so nothing else will refresh it. It also re-queries whenever the display's time range changes.
Time range
Fallback only. The display's own time range wins whenever the URL carries one, which is how this symbol follows the time bar without a data pipeline to be told through. PI time grammar: *-7d, t, y+6h, or an absolute timestamp. Every duration on the chart is clipped to this window — an event that ran for three days but only two hours of it fall inside the window contributes two hours.
Grouping
The most valuable grouping there is, and the most expensive: it needs one value per event. They are fetched in a single batched request rather than one request per event, and any sub-requests that fail are counted in the footer instead of quietly landing those events in "(unassigned)" without explanation. The name must match the Event Frame template exactly.
Downtime reasons are very often buried in the event name, and a regular expression is the only way to get them out without touching the AF model. Capture group 1 becomes the group — the pattern - ([A-Z]+)- turns Downtime - Mill 1 - MECH-04 into MECH. Leave it blank to group by the whole event name. An invalid expression is reported in the footer, not swallowed.
Events with no value for whatever you grouped by go into an explicit "(unassigned)" group rather than being dropped. That group is frequently the finding: nobody is filling the reason code in.
Ranking
Total duration is the cost; count is the nuisance. They frequently disagree, and the disagreement is usually the interesting part. Total duration merges overlapping events within a group before summing — two operators logging the same outage twice must not book it twice — and the footer says when merging changed the total.
Both assume the parts add up to the whole, so they are suppressed automatically when the metric is a mean or a maximum — those do not sum, and a cumulative percentage of them would be a made-up number.
0 shows every group. "Other" keeps the cumulative line honest — without it the percentages are taken over a subset and every share looks bigger than it is.
Presentation
Automatic gives the human form (2d 4h), which reads fastest on a wall display. Pick an explicit unit when the number is going to be copied into a report and has to be comparable — 52.3 h rather than 2d 4h.
Threshold bands are compared against the value in the duration unit above — the only unit you saw when you typed the numbers. With "Automatic" that unit is chosen from the data, so pick an explicit one before setting thresholds on a duration.
Event count, total time, how much of the window is covered once overlaps between groups are removed, and that as a percentage of the window.
An event with no end time is still running. It is counted up to now, so its group's total grows every minute — a figure that silently includes one is a different number tomorrow, and this is the line that says so.
Click
The target display opens over the clicked group's own span — first event start to last event end — because the reason to click a reason code is to see what the plant was doing while it was happening.
