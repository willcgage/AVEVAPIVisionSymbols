Buttons
Builds the buttons from the current asset's place in AF: Up to its parent, a breadcrumb of its ancestors, and its siblings. Each switches the asset; a level with a display below opens that display as well. The Items list is not used.
Used when the display was opened without an asset. Left blank, the element of the attribute dropped onto the panel is used.
Siblings and children are listed through PI Web API (set up once per site in pvx-config.js). Without it Up and the breadcrumb still work, and the panel says what is missing.
Levels count from the top of the AF database: 1 is its top-level elements. Raise this to hide enterprise levels above the plant; Up stops there too.
One line per level. * covers every level without a line. A level with no display keeps this display and only changes the asset.

A string attribute whose value is the menu, in the same one-button-per-line form as the list below. Every display that names it shows the same buttons, and a change in AF reaches all of them within a minute, without editing a display. Until it is read, or if it cannot be, the list below is used and the panel says why.
Format: Label | target | extra
Blank lines are ignored, and a line starting with # is a comment. Spaces around the | are trimmed.
Icon and tooltip — start the label with an icon name in brackets, and put the tooltip after --: [home] Overview -- Plant overview | 101. A label of only an icon, such as [back], makes an icon button. Icons: home, back, forward, up, down, trend, alarm, table, gauge, clock, map, list, settings, info, report, power, star, menu, external, kiosk, toolbar, timebar, sidebar, plant, search.
Address from data — write {value} in a target and the button uses the current value of this symbol's data source there, so an AF attribute can hold the display id or asset path: Details | {value}.
Open a display — target is the display id (or id/slug, a path starting with /, or a full http(s) URL). Optional extra is an AF element path passed as ?asset=.

Switch asset — target is the AF element path. The current display stays put and only the asset context changes.

Set time range — target is the start time in PI time syntax and extra is the end time (defaults to *, now).

Custom — target is a display id (leave it blank to stay on this display) and extra is a list of key=value pairs separated by semicolons. Supported keys: asset, start, end, mode. 
Boiler 3, last shift | 1058 | asset=\\PISRV01\Plant\Boiler 3;start=*-8h;end=*
Reset time here      |      | start=*-24h;end=*
Finding a display id: open the display and look at the browser address bar. The id is the number straight after /Displays/ — in .../PIVision/#/Displays/1042/Boiler-Overview the id is 1042. The name after it is cosmetic and may be omitted; it is ignored when matching the active button.

Appearance
Leave blank for a darker shade of the button color.
Behaviour
Compares each button against the display's current URL — the display id, the asset path, or the start/end times, depending on the mode above.
A value set by the button itself always wins over the carried-over one.
The first click turns the button into Confirm? for four seconds; a second click within that window navigates. It cancels itself on timeout, on losing focus, or when another button is clicked. No pop-up dialog is used — a modal would block the display's data updates.
