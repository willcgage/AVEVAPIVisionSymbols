Event source
This symbol reads Event Frames from PI Web API, not from PI Vision's own data pipeline, so it has no attribute drop target. If it says PI Web API is not configured, set baseUrl in ext/libraries/pvx/pvx-config.js on this PI Vision server and confirm it with ext/piwebapi-check.html.
* and ? wildcards, as in PI Web API.
The asset is the one in the display's URL, or else the element of the attribute this symbol was placed with, so one template display shows the events of whichever area or complex it is opened on. Below the asset, each element is one sub-request in a single batch, and the footer says when the element limit cut the search short.
Overlapped is almost always what you want, and it is the default for a reason: an event that started before the window and is still running is exactly the one an operator is looking for, and every stricter mode drops it. Inclusive only returns events that both started and ended inside the window, which quietly hides the trip that is happening right now.
If more match, the footer says so — it never silently shows a subset.
This symbol has no PI Vision data pipeline, so nothing else will refresh it. It also re-queries whenever the display's time range changes.
Time range
Fallback only. The display's own time range wins whenever the URL carries one, which is how this symbol follows the time bar without a data pipeline to be told through. PI time grammar: *-8h, t, y+6h, or an absolute timestamp.
Swimlanes
For batches and other parent/child Event Frames: each frame gets its own row, its children indented beneath it. The filters above pick the top-level frames; their children are fetched one level per batched request.
Per-asset lanes need one extra lookup to turn each referenced element into a name. It is done in a single batched request and cached, so it costs nothing after the first refresh.
When there are more, the lanes with the most event time are kept — dropping the least-affected assets is the only truncation that leaves the chart meaningful. The footer reports how many lanes and events were left out.
Colour
Typical is the median duration of finished frames of the same kind in this window: same template, and below the top level, the same name. Amber past the tolerance, red past twice it; a tick on each bar marks where a typical frame would have ended. A kind needs three finished frames to have a typical.
One value per event, fetched in a single batched request rather than one request per event. Text values get a palette colour each; numeric values use the threshold bands below.
Bars
An event with no end time has not finished. It is drawn to the right edge with a pointed end rather than a square one, because a square end reads as "finished exactly here" — which is a lie about a fault that is still on the plant.
A 20-second trip on an 8-hour window is a third of a pixel wide, and it is often the most interesting mark on the chart. This is the floor that keeps it visible.
Both are dropped automatically once the symbol is too small to hold them.
Chrome
Drawn only when the window actually contains now.
Click
The target display opens on the clicked event's time range, not the current one — the reason to click a bar is to see what everything else was doing during it.

Advanced
Leave this blank in production. The base URL belongs in ext/libraries/pvx/pvx-config.js, where one site setting serves every symbol and survives an upgrade. Use this only to point at a second PI Web API — a test instance, or another plant's server. It moves the base URL for every PVX symbol on the page, because PVX.api is deliberately one shared client so that authentication is configured once per site. Two symbols with two different overrides on one display will fight.
