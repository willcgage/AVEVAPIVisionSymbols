Target
An AF attribute is \\<AF server>\<database>\<element>|<attribute>; a PI point is \\<data server>\<tag>. Both resolve through the same endpoint, so either works here. The path is resolved to a WebID once and the WebID is reused — the value is never cached.
This symbol writes through PI Web API, not PI Vision's data pipeline, so it has no attribute drop target. If it says PI Web API is not configured, set baseUrl in ext/libraries/pvx/pvx-config.js on this PI Vision server and confirm it with ext/piwebapi-check.html.
Who may write is decided by PI and AF security, not by this symbol. If the write comes back "not permitted", the fix is a write mapping on the AF database or the PI point — there is no setting here that can grant it.

Confirmation
Leave this on. There is no undo on a PI write. Turning it off is only reasonable for a value that is trivially correctable and typed dozens of times a shift.
{value}, {name}, {units} and {path} are substituted. Keep {value} and {name} in the sentence: a confirmation that only asks "are you sure?" trains people to click it without reading, which is worse than having none.
Timestamp
"When it is written" sends * and lets PI stamp it — the historian's clock is the authority and a browser's clock is routinely minutes out. Choose the second for the reading that was taken at 06:00 and typed in at 07:15, which is the normal case for rounds and lab results. The operator's field accepts 2026-08-08 06:00 or * with an offset such as *-2h.
Off by default: a future timestamp is nearly always a typed year or a mixed-up day, and it sits in the archive ahead of every real value until it arrives. A minute of slack is allowed regardless, because clocks disagree.
Current value
This symbol has no PI Vision data pipeline, so nothing else will refresh it. The refresh pauses while a confirmation is open or a write is in flight, so the number the operator approved cannot move under them.
A failed read is reported in the value line only. It never blocks the write — read and write are separate permissions in PI, and having one without the other is normal.
Button and history
The writes made from this symbol on this display, so the operator can see their own last few entries without leaving the screen. It lives in memory and is gone when the display closes — PI is the record, not this list. It is dropped automatically when the symbol is too short to hold it.
Chrome
Below roughly 200 × 140 pixels the form is not usable and the symbol says so by name instead of drawing a squeezed version of itself. A cramped entry field is a mis-typed write waiting to happen.
Advanced
Renders the whole form and refuses to write. This is for building and reviewing a display before the AF write permissions exist, so the layout can be agreed without anyone putting a test number into the historian. Clear it when you go live.
